# Internal guarded location resolver

`createGuardedLocationResolver` is an internal assembly, not a CLI. Its bound Node HTTP(S) transport issues one GET, follows no redirects, uses no retry mechanism, and bounds response bodies to 1 MiB. It drains success and error bodies. The attempt remains guarded until the request and its local socket have closed, including after abort, response failure or an oversized body. JSON parsing is also under the lock. If local termination cannot be established the attempt does not settle, so the lock is not released. The explicitly named `createGuardedLocationResolverForTest` seam is for synthetic transports only; its injected transport must settle only after local termination and must never be used for provider traffic. No live-provider behavior has been validated.

Cache key locks are acquired before the shared attempt lock; no path acquires them in reverse. Independent operator retries are new guarded invocations; there are no automatic retries. The 30-second caller timeout requests abort but does not establish that the remote request stopped. The attempt lock remains held until local termination and successful body parsing settle. Lock acquisition waits are bounded; congestion or a stale lock fails closed. A timed-out operation may continue in the background and hold the attempt lock. Cache key ownership is released on caller timeout; the shared attempt lock still prevents another transport attempt until settlement. Local socket closure proves neither that a remote server stopped processing nor that it stopped downstream activity.

Use a private local directory shared by all participating processes. This does not coordinate other directories, installations, machines, or clients and cannot enforce aggregate provider limits. Check current provider terms and usage policy independently; caching does not establish data or export rights. Cache files contain queries only via hashed keys but contain results and attribution; protect and delete them according to local requirements. Delete cache data only while all participating processes are stopped.

A crash can leave either key or attempt locks, temporary files, or uncertain timing state. Do not remove a lock while any prior process or request could still be active. Stop all participants, establish that prior requests have terminated and wait at least the provider spacing interval, then inspect and remove stale lock directories; preserve the timing file. Invalid timing or wall-clock regression fails closed and may retain the attempt lock. Correct the clock and inspect timing state before recovery; if timing cannot be trusted, wait conservatively after all activity has ceased before deliberately resetting it. This manual recovery cannot prove remote activity has ended. Filesystem permissions, reliable local atomic directory creation and rename, and an accurate wall clock are operator responsibilities.
