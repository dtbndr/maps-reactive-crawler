# Internal guarded location resolver

`createGuardedLocationResolver` is an internal assembly, not a CLI or a production HTTP transport. Supply one local operator-scoped cache directory, endpoint, identification, and a strictly single-attempt transport. The transport must honor `redirect: 'error'` and the abort signal, never retry or redirect internally, and settle only after the entire response body (including non-success responses) has been received or terminated. Successful JSON parsing also remains under the attempt lock. An ordinary streaming `fetch` response alone does not satisfy this contract. No production transport is supplied or validated here. Only a compliant transport can ensure that every HTTP request passes the coordinator.

Cache key locks are acquired before the shared attempt lock; no path acquires them in reverse. Independent operator retries are new guarded invocations; there are no automatic retries. The 30-second caller timeout requests abort but does not establish that the remote request stopped. The attempt lock remains held until the transport and successful body parsing actually settle. Lock acquisition waits are bounded; congestion or a stale lock fails closed. A timed-out operation may continue in the background and hold the attempt lock. Cache key ownership is released on caller timeout; the shared attempt lock still prevents another transport attempt until settlement.

Use a private local directory shared by all participating processes. This does not coordinate other directories, installations, machines, or clients and cannot enforce aggregate provider limits. Check current provider terms and usage policy independently; caching does not establish data or export rights. Cache files contain queries only via hashed keys but contain results and attribution; protect and delete them according to local requirements. Delete cache data only while all participating processes are stopped.

A crash can leave either key or attempt locks, temporary files, or uncertain timing state. Do not remove a lock while any prior process or request could still be active. Stop all participants, establish that prior requests have terminated and wait at least the provider spacing interval, then inspect and remove stale lock directories; preserve the timing file. Invalid timing or wall-clock regression fails closed and may retain the attempt lock. Correct the clock and inspect timing state before recovery; if timing cannot be trusted, wait conservatively after all activity has ceased before deliberately resetting it. This manual recovery cannot prove remote activity has ended. Filesystem permissions, reliable local atomic directory creation and rename, and an accurate wall clock are operator responsibilities.
